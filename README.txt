FiribStop UZ — Live Threat Map 2.3.0
=================================

Конкурсная сборка с офлайн-проверками, настоящей геометрией административных регионов и онлайн-лентой кибербезопасности. Для онлайн-новостей нужен Node.js сервер; сторонние API-ключи не нужны.

Что работает офлайн
- Локальный анализ подозрительных сообщений и ссылок по эвристическим правилам.
- История проверок и статистика на устройстве.
- Учебные сценарии, викторина, памятки и режим для родителей.
- Проверка силы пароля в браузере: введённый пароль не отправляется и не сохраняется.
- Android-сканер APK (статический анализ) и карантин в приватном хранилище приложения.
- Экспорт/резервное копирование поддерживаемых локальных данных.

Запуск веб-версии
1. Распакуйте ZIP.
2. Откройте firibstop_uz_secure/index.html в современном браузере. Для установки PWA используйте HTTPS-хостинг; для локального теста можно открыть файл напрямую, но некоторые функции браузера могут быть ограничены.

Android
1. Откройте папку android/ в Android Studio (JDK 17 и Android SDK).
2. Дождитесь синхронизации Gradle и соберите APK.
3. Протестируйте на реальном устройстве, особенно выбор APK, передачу ссылок, разрешения и карантин.

Важные ограничения
- Локальные проверки — эвристика, не полноценный антивирус и не гарантия безопасности. Отсутствие предупреждения не означает, что ссылка или файл безопасны.
- Сканер APK анализирует доступные статические признаки и не запускает приложение. Возможны ложные срабатывания и пропуски.
- Оценка пароля выполняется только по базовым правилам и не проверяет базы утечек. Не вводите свой настоящий пароль на чужом или публичном устройстве.
- История хранится локально; очистка данных браузера может её удалить.
- Локальные проверки доступны без сервера. Онлайн-лента новостей и загрузка GeoJSON требуют работающего сервера и интернета. Лента собирает опубликованные RSS-бюллетени и новости, а не телеметрию атак в реальном времени.

Перед публикацией
- Проверьте сборку Android Studio и все сценарии на устройстве.
- Подготовьте собственную подпись приложения и политику конфиденциальности.
- Не заявляйте о 100% обнаружении мошенничества или вредоносных APK.


Версия 2.2.0: карта регионов обновлена. Используется интерактивная Leaflet-карта и открытая геометрия административных регионов, получаемая из GeoJSON-источника и кешируемая в браузере после успешной загрузки. Подложка OpenStreetMap и загрузка библиотеки Leaflet требуют интернета. При недоступности сети приложение показывает понятное сообщение и оставляет доступным выбор региона из списка.

Надёжность карты: окраска регионов не выдаёт оценку опасности; отсутствие новостей не отображается как «безопасно». Совпадения по тексту публикаций называются упоминаниями, а не подтверждёнными атаками. В карточке региона доступны ссылки на официальные источники. Важно: приложение не подключено к официальному потоку инцидентов и не является системой мониторинга атак в реальном времени.

Публикация веб-версии по HTTPS: загрузите содержимое папки firibstop_uz_secure в репозиторий GitHub, включите Settings → Pages → Deploy from a branch → main / root. После публикации GitHub Pages выдаст адрес вида https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/. Если нужен собственный домен, добавьте его в Settings → Pages → Custom domain и настройте DNS-записи у регистратора; затем дождитесь включения HTTPS в настройках Pages. Не загружайте секреты, ключи или личные данные в публичный репозиторий.


Версия 2.3.0 — онлайн-лента и карта
- server.js предоставляет /api/news, /api/attacks, /api/analytics, /api/regions и /api/health.
- Источники RSS: CISA (официальные бюллетени и новости), BleepingComputer и SecurityWeek. У каждой записи есть ссылка на оригинал, дата, источник и категория.
- Сборка не использует API-ключи. Сервер обновляет RSS примерно каждые 10 минут и сообщает статус каждого источника.
- Карта получает GeoJSON регионов через /api/regions, затем сохраняет его в localStorage. Подложка OpenStreetMap и библиотека Leaflet загружаются из интернета; для полностью офлайн-карты их ресурсы нужно отдельно встроить в приложение.
- Географическая привязка новостей по совпадению названия региона является только упоминанием. Карта не отображает подтверждённую телеметрию кибератак и не должна называться live attack tracker.

Локальный запуск сервера
1. Установите Node.js 18 или новее.
2. В папке проекта выполните: npm start
3. Откройте http://localhost:3000.
4. Проверьте http://localhost:3000/api/health и http://localhost:3000/api/news.

Публикация по HTTPS через Render
1. Загрузите папку проекта в свой GitHub-репозиторий (не добавляйте пароли/секреты).
2. В Render создайте New → Web Service и подключите этот репозиторий.
3. Build Command: npm install (зависимостей нет, можно также оставить пустым, если Render разрешает). Start Command: npm start. Runtime: Node.
4. После Deploy Render выдаст HTTPS-адрес вида https://имя-сервиса.onrender.com. Откройте его: сайт и API работают на одном домене.
5. Если веб-страница опубликована на другом домене или APK использует отдельный адрес, в разделе «Настройка сервера» введите HTTPS-адрес Render и нажмите «Сохранить адрес».
6. Проверяйте /api/health и /api/news. В разделе новостей смотрите статус источников. Бесплатный хостинг может засыпать и задерживать первое обновление.

Важно: GitHub Pages — статический хостинг и не запускает server.js. Для этой версии с RSS-прокси нужен Node.js-хостинг (например, Render) либо отдельный backend. RSS-источники могут временно быть недоступны; в этом случае приложение должно показывать статусы ошибок и не придумывать инциденты.
